# process dies with ModuleNotFoundError during startup instead of at first use.
# This file is the delta that makes the "min" set actually boot, with the same
# pins the repo uses in backend/requirements.txt so versions never drift from the
# main dependency set.
#
# Verified: `requirements-min.txt` + this file boots the app to a healthy
# `GET /health -> {"status":true}` with ~340 MB RSS and no PyTorch /
# sentence-transformers / faster-whisper installed.

# Deliberately NOT installed here (all optional, imported lazily, and each one is
# hundreds of MB): torch, torchvision, sentence-transformers, faster-whisper,
# docling, markitdown, unstructured, tika, opencv, playwright. Anything in
# Settings that needs them must stay disabled — see deploy/README.md.

## Database drivers not in requirements-min
# internal/db.py runs TWO engines: the async one (all runtime queries) uses psycopg v3,
# which requirements-min does ship, but the sync one - startup migrations, config loading,
# alembic, health checks - uses SQLAlchemy's default `postgresql` dialect, which is psycopg2.
# Without this line, setting DATABASE_URL=postgresql://... dies at boot with
# "ModuleNotFoundError: No module named 'psycopg2'" from run_migrations(), which re-raises.
# Verified against sqlalchemy==2.0.50 in a clean venv: create_engine('postgresql://') raises
# without it and reports dialect.driver == psycopg2 with it.
psycopg2-binary==2.9.12       # same pin as backend/requirements.txt
